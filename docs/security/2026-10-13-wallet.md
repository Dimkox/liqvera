## Fix and verification

The official SDK supplies BigInt permit fields. Plain JSON serialization failed before reaching the wallet and the browser incorrectly showed payment recovery. The adapter now uses viem's serializer with explicit EIP712Domain fields for Permit2 and MUSD. A wallet rejection (4001) during either signature is a known pre-submission cancellation; failures after submission remain confirm-only.

Four real-adapter/official-SDK regression cases failed before correction and pass afterward. All 35 browser tests and the Testnet production build pass. Independent code and rollout reviews found no remaining blocker. No HTML/CSS was edited.

A real Chrome check against the deployed service reproduced zero wallet calls before the repair. After deployment, the exact decimal amount reaches the injected wallet provider as a string; rejecting it displays cancellation and enables retry. The same check renders the historical preview and generates a fresh public-market quote. This uses a rejecting provider stub, not a real signed purchase. Historical successful paid Testnet evidence remains separate and valid.
