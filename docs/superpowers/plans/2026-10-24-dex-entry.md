# Market depth DEX Entry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add an opt-in Mezo DEX comparison to Market depth requests and surface the existing fresh-quote wallet sale planner in the workspace.

**Architecture:** Carry an optional literal-true DEX selection through web session, gateway request/capabilities, report service and build verification. Preserve absent-field behavior for old callers. Render the sale planner independently from report delivery, gated by published capabilities and backed by the existing wallet execution adapter.

**Tech Stack:** TypeScript, Node tests, Python report service/tests, Vite browser build.

**Spec:** `docs/superpowers/specs/2026-10-24-dex-entry-design.md`; canonical product constraints in `docs/specification.md`.

## Global Constraints

- Market evidence stays public and read-only.
- User wallet signatures remain required for every approval and swap; no signing keys enter Liqvera.
- Existing Hyperliquid-only requests, immutable reports, sealed bundles and SQL migrations remain compatible.
- No live payment or swap is part of testing.

## Review Focus

- DEX unavailable on Mainnet/fixture or when either runtime flag is off → checkbox absent and request rejected closed.
- Old session/request shapes without the DEX field → remain recoverable and Hyperliquid-only.
- DEX evidence missing or mismatched for an opted-in request → quote build rejected, never silently downgraded.
- Wallet/account/network changes while planning → execution remains blocked by existing context guards.
- Per-slice quote changes beyond the 1% impact cap → re-plan before requesting a signature.
